Benchmark:
365.19 complete users/second overall.
600,000 contacts generated in 1642.99 seconds of measured SQL wall time.
  en_US: 409.79 users/second (3 x 100,000 contacts)
  de_DE: 329.34 users/second (3 x 100,000 contacts)

Every contact includes all requested fields. The procedure serializes and hashes every generated contact. SQL timing includes generation, serialization, and checksumming, but excludes HTTP, HTML rendering, and network transport. Client round-trip times are reported separately. Measured on a shared VPS: AMD EPYC, 4 vCPUs, PostgreSQL 18.6, database container memory limit 384 MiB.

Source code:
https://github.com/e7ol7e/itransition-task6

All user-data generation is performed by 15 PostgreSQL stored procedures. Python calls the procedures and renders the application. Includes two locales, deterministic seed/position-based pagination, locale-keyed lookup tables, SQL-trained Markov street names, uniform sphere coordinates, normal-distribution physical attributes, varied name/address/phone formats, and CSV/JSON exports.
